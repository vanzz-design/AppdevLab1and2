    What to notice

    • 401 and 403 mean different things. 401 Unauthorized: the server does not know who you are, so sign in. 403 Forbidden: it knows exactly who you are, and your role does not allow the action.
    • Authorization needs authentication first. Without a valid token every protected action stops at 401. The page checks the token's signature and expiry before it trusts anything in it.
    • Permissions live apart from the login. The token names the user. The role comes from a separate record, like our profiles table, so an admin can change it without anyone signing in again.
    • The role menu is only for the demo. In the real system users cannot edit their own role: a database trigger resets role, strike_count, and suspended_until on any update that does not come from an admin.
    Hiding a button is not authorization

    The web app hides the Admin link from students, but that is only a convenience. The real protection is the database policy shown in "The rule behind it", which still blocks the request if someone calls the API directly.
